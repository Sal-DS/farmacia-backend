# Fluxo de trabalho

- Para cada nova feature, criar uma branch própria a partir de `development`, preferencialmente com o prefixo `feat/`.
- Toda alteração deve passar por pull request com destino à branch `development`.
- Não realizar commits diretamente em `development`, `main` ou `staging`.
- Preservar alterações locais existentes e incluir no PR apenas mudanças pertencentes à tarefa.
